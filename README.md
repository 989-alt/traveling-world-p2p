# 돌아라! 지구 한 바퀴

세계의 여러 나라를 여행하는 4인 온라인 보드게임. Preact + Vite. 게임 서버가 없다 — 방을 만든 기기의 브라우저 탭이 방을 돌리고, 다른 기기는 WebRTC(PeerJS)로 그 기기에 직접 붙는다.

```bash
npm ci               # Node 22.18 이상
npm run dev          # 클라이언트 개발 서버
npm run typecheck
npm run build        # dist/
npm test             # vitest
npm run e2e          # playwright
npm run check:sources   # 출처 흔적 0건 (빌드 뒤)
npm run check:bundle    # 첫 로드 ≤ 3 MB (빌드 뒤)
npm run check:static    # 서버 호출·절대 경로·서비스워커 0건 (빌드 뒤)
npm run check:firstload # 정답 글이 방장용 파일에만 있는지 (빌드 뒤)
```

- 정적 에셋: `assets/` (개발 서버의 `publicDir`. 빌드는 `webp/*.webp`·`audio/*.mp3` 만 dist 로 복사)
- 디자인 토큰: `src/styles/tokens.css`. 다른 CSS 는 `var(--이름)` 만 쓴다.

## 납품 안내 (올리는 분께)

### 올리는 법

1. `dist/` **폴더 안의 파일 전부**를 그대로 정적 호스팅에 올린다. 올릴 양은 **파일 1,483개, 177.5 MB**다(2026-11-24 빌드. 대부분 그림이고, 한 기기는 그때그때 쓰는 것만 받는다. 첫 화면의 js·css 는 약 0.8 MB). 서버 프로그램, 데이터베이스, 주소 다시 쓰기(rewrite) 설정은 필요 없다.
2. 어느 하위 경로든 된다. 예: `https://example.com/games/world/`. 모든 파일을 상대 경로로 찾으므로 빌드를 다시 하지 않아도 된다.
3. 주소는 `/games/world/`(끝에 `/`) 또는 `/games/world/index.html` 로 연다. 끝에 `/` 가 없는 `/games/world` 는 서버가 `/games/world/` 로 넘겨 줘야 한다(대부분의 서버는 저절로 넘긴다). 안 넘기는 서버라면 링크에 `/` 를 꼭 붙인다.
4. **HTTPS 가 필수다.** 기기 간 연결, 화면 꺼짐 방지, 방 잠금이 HTTPS 에서만 온전히 돈다. `index.html` 을 두 번 눌러 파일로 여는 방식(`file://`)은 되지 않는다.
5. 서버가 확장자별 형식(MIME)을 알아야 한다: `.js` `text/javascript`, `.webp` `image/webp`, `.mp3` `audio/mpeg`, `.webmanifest` `application/manifest+json`. 모르는 확장자를 404 로 막는 서버(예: IIS)는 `.webp`·`.webmanifest` 를 등록한다.
6. 캐시: `assets/` 안의 js·css 는 파일 이름에 내용 해시가 있어 오래 캐시해도 된다. `index.html` 은 캐시하지 않거나 짧게 둔다. `webp/`·`audio/` 는 이름이 그대로이므로 그림을 바꿔 올린 때는 캐시를 비운다.
7. 새 판을 올릴 때 옛 `assets/` 파일을 바로 지우지 않는 편이 좋다. 이미 열어 둔 화면이 방을 만들 때 옛 파일을 찾는다(없으면 새로고침해야 한다). 한 방의 네 기기는 같은 판을 열어야 한다.

### iframe 으로 넣을 때

- `<iframe src="https://…/world/" allow="screen-wake-lock; autoplay; fullscreen">` 처럼 **`allow="screen-wake-lock"`** 을 넣는다. 없으면 방장 기기 화면이 저절로 꺼져 판이 멈출 수 있다.
- `sandbox` 를 쓴다면 `allow-scripts allow-same-origin` 이 있어야 한다.
- **저장이 바깥 페이지별로 갈린다.** iframe 안에서 만든 방은 같은 게임 주소를 새 탭으로 직접 열면 보이지 않는다. 이어 할 때는 처음과 같은 길로 연다.
- 일부 브라우저(Safari)는 iframe 안의 저장을 브라우저를 닫을 때 지울 수 있다(추정, 실기기 미확인). 이어 하기가 중요하면 새 창으로 여는 쪽이 안전하다.

### 바깥으로 나가는 주소

| 주소 | 쓰는 곳 | 막히면 |
| --- | --- | --- |
| `0.peerjs.com:443` (https·wss) | 시그널링: 방 코드로 상대 기기 찾기 | 다른 기기와 같이 못 한다. 로봇과 하는 판은 된다 |
| `stun.l.google.com:19302`, `stun1.l.google.com:19302` (UDP) | STUN: 서로 다른 망에 있는 기기가 만날 주소 찾기 | 같은 와이파이 안에서는 될 수 있다. 다른 망끼리는 못 붙는다 |
| `fonts.googleapis.com`, `fonts.gstatic.com` | 글꼴 | 기기의 글꼴로 뜬다. 게임은 그대로 된다 |

- 시그널링 서버를 지나는 것은 **연결 ID(방장은 `twj1-<방 코드>`, 학생 기기는 서버가 주는 임의 값)와 기기의 IP·포트(연결 협상)**다. STUN 서버도 기기의 IP·포트를 본다. **문항·답·점수 같은 게임 데이터는 시그널링·STUN 서버를 지나지 않고** 기기끼리 직접 오간다. 중계(TURN) 서버는 쓰지 않는다.
- 배포 파일을 검색하면 `turn:eu-0.turn.peerjs.com:3478` 같은 TURN 주소 글자열이 나온다. PeerJS 라이브러리의 기본값이 코드에 남은 것이고, 게임이 연결 설정(`iceServers`)을 늘 직접 주어 덮어쓰므로 쓰이지 않는다.
- 이름·계정·전화번호 같은 개인정보를 묻지도 저장하지도 않는다.
- 공용 시그널링·STUN 은 남이 운영하는 무료 서비스라 끊기지 않는다는 보장이 없다.
- CSP 를 쓰는 사이트라면 `connect-src` 에 시그널링 주소(`https://`·`wss://`)와 자기 주소, `style-src`·`font-src` 에 글꼴 주소를 넣는다. 글꼴 줄은 인라인 `onload` 를 쓰므로 인라인 스크립트를 막으면 글꼴만 안 붙는다.

### 주소 바꾸기 (`VITE_TW_*`)

주소는 빌드할 때 파일에 박힌다. **이미 만든 `dist/` 의 설정만 바꿀 수는 없고**, 소스에서 아래 값을 주고 다시 빌드한다.

```bash
VITE_TW_PEER_HOST=peer.example.com \
VITE_TW_PEER_PORT=443 \
VITE_TW_PEER_PATH=/ \
VITE_TW_ICE_SERVERS='[{"urls":"stun:stun.example.com:3478"}]' \
npm run build && npm run check:static && npm run check:firstload
```

| 값 | 기본 | 뜻 |
| --- | --- | --- |
| `VITE_TW_PEER_HOST` · `VITE_TW_PEER_PORT` · `VITE_TW_PEER_PATH` | `0.peerjs.com` · `443` · `/` | 시그널링 서버(PeerJS 서버, npm `peer`) |
| `VITE_TW_PEER_SECURE` | `true` | `false` 면 http·ws(개발용. HTTPS 페이지에서는 막힌다) |
| `VITE_TW_ICE_SERVERS` | 위 STUN 2곳 | JSON 배열. `[]` 면 STUN 없이 같은 망에서만 |
| `VITE_TW_RETAKE_GIVE_UP_MS` | `150000` | 방장이 방을 다시 열 때 옛 등록이 풀리기를 기다리는 시간 |
| `VITE_TW_NET` | `peer` | `ws` 는 Cloudflare 판(아래 롤백). 정적 납품에는 쓰지 않는다 |

자체 시그널링 서버의 옛 등록 보관 시간(`alive_timeout`, 기본 90초)을 90초보다 길게 잡으면 `VITE_TW_RETAKE_GIVE_UP_MS` 도 그보다 길게 잡는다.

### 방장 기기 규칙

- **방을 만든 기기(방장)가 방이다.** 놀이가 끝날 때까지 그 창을 닫거나 다른 앱으로 가지 않는다. 전원을 연결해 두면 좋다.
- 방장 창이 닫히거나 기기가 잠들면 친구 기기는 "방장 기기를 기다리고 있어요"에서 기다린다. 방장이 **같은 기기·같은 브라우저**로 다시 열면 멈춘 자리에서 [게임 계속하기]로 잇는다. 다른 기기로 방장을 옮길 수는 없다.
- 새로고침은 보통 몇 초 안에 다시 열린다. **방장 기기가 인터넷이 끊긴 채 꺼졌다 켜지거나 브라우저가 강제 종료되면 94~99초쯤 걸릴 수 있다.** 시그널링 서버가 옛 등록을 쥐고 있기 때문이다(공용 서버 `0.peerjs.com` 2026-11-25 실측 4회: 93.7~99.0초, 다시 연 뒤로는 91.8~96.6초). 게임은 150초까지 저절로 다시 시도한다. 그보다 오래 쥐면 [다시 해 보기]를 한 번 더 누른다.
- **방장 기기가 꺼진 동안에는 같은 코드의 연결 ID(`twj1-<방 코드>`)를 남이 잡을 수 있다.** 연결 ID 에는 암호가 없고, 코드를 아는 사람이면 된다. 그러면 방장은 방을 다시 열 수 없고("방을 다시 열지 못했어요"와 방 코드가 뜬다. 저장된 판은 그대로), 그 사이 다시 붙으려는 친구 기기는 그 사람에게 이어지며 자리 번호(숫자 4자리)를 보낼 수 있다. 개인정보는 들어 있지 않다.
- 같은 기기에서 같은 방을 두 창으로 열 수 없다.
- 방장이 채점하므로 정답이 배포 파일(방을 만들 때만 받는 `assets/host-net-*.js`)에 들어 있다. 학생 기기 화면과 학생 기기로 가는 메시지에는 푸는 동안 정답이 없지만, 배포 파일을 열어 보거나 방장 기기를 개발자 도구로 보면 알 수 있다.

### 저장

- 판은 방장 기기 브라우저에만 저장된다(서버 저장 없음). 시크릿 창이나 저장을 막은 기기에서는 판은 되지만 "이 기기에는 놀이를 저장할 수 없어요"가 뜨고, 창을 닫으면 이어 할 수 없다.
- 저장하는 곳은 `localStorage` 이고, 강제 종료에 대비한 같은 내용의 사본을 그 기기의 `IndexedDB` 에도 둔다(브라우저가 강제 종료되면 `localStorage` 가 최대 1분 앞으로 되돌아갈 수 있어, 다음에 열 때 더 새로운 사본으로 되찾는다). 사본에도 개인정보는 없다. 전원이 갑자기 꺼진 경우는 확인하지 못했다.
- 저장은 사이트 주소(출처)마다 따로이고 하위 경로로는 갈리지 않는다. 같은 사이트의 다른 앱과 약 5MB 를 나눠 쓴다.
- 80분 판 하나가 약 18만 자다. 5MB 에 80분 판 14~28개(브라우저가 글자를 세는 방식에 따라 다름).
- **한 기기를 여러 반이 방장으로 쓰다가 저장할 자리가 모자라면**: 끝난 판과 14일 지난 판을 오래된 것부터 저절로 지우고 이어 저장한다. 하다 만 판은 저절로 지우지 않는다. 그래도 자리가 없으면 "지금부터는 놀이가 저장되지 않아요. 창을 닫으면 조금 전으로 돌아가요"가 뜨고, 판은 계속되지만 그 뒤 진행은 창을 닫으면 사라진다.
- **자리를 비우는 법**: 하다 만 판은 그 방 코드로 열어 [게임 끝내기]를 누른다(그 판의 기록이 지워진다). 급하면 브라우저 설정에서 이 사이트의 저장 데이터를 지운다(그 기기의 판이 모두 지워진다).
- 마지막으로 쓴 지 14일이 지난 판은 그 기기에서 게임을 열 때 지워진다. 14일은 게임이 지우는 때이지 그때까지 남는다는 보장이 아니다. **브라우저가 먼저 지울 수 있다**(사파리처럼 한동안 열지 않은 사이트의 저장을 지우는 브라우저, 저장 공간 부족, 기기 관리 정책. 실기기 미확인).

### 학교망 조건

- 시그널링 주소가 열려 있어야 하고, **같은 와이파이의 기기끼리 직접 통신할 수 있어야 한다.** 무선 공유기의 "기기 간 통신 차단(AP 격리)"이 켜진 망에서는 못 붙는다. 중계 서버를 쓰지 않아 돌아갈 길이 없다.
- 이런 학교에서는 한 사람 + 로봇 셋 판만 된다. 이때 방장 대기실에는 "친구 기기와 연결할 수 없어요", 학생 기기에는 "방에 들어갈 수 없어요"가 뜬다.

### 아직 확인하지 못한 것

자동 시험은 데스크톱 Chromium 과 이 컴퓨터 안의 시그널링 서버로만 했다. 다음은 실제로 해 보지 않았다.

- 실제 학교 와이파이에서 기기 네 대가 한 방에 붙는 것, 서로 다른 망의 기기가 붙는 것
- 아이패드(Safari)·크롬북·안드로이드 태블릿을 방장으로 한 판(화면 꺼짐 방지, 다른 앱 갔다 오기, 저장이 남는지)
- 공용 시그널링 서버(`0.peerjs.com`)와 공용 STUN 을 거친 연결
- iframe 안에서의 저장·화면 꺼짐 방지, 실제 납품 서버에 올린 주소

### 롤백 (Cloudflare 판)

게임 서버가 있는 옛 방식(Cloudflare Workers + Durable Objects)을 그대로 남겨 두었다. Cloudflare 계정이 있어야 한다.

```bash
VITE_TW_NET=ws npm run build   # 웹소켓 판 dist/
npx wrangler deploy            # worker/ 와 dist/ 를 함께 배포(wrangler.toml)
```

이 판은 사이트 맨 위 주소(`/`)에서만 돌고 `/api/` 를 부르므로 `check:static` 이 일부러 실패한다. 정적 납품으로 돌아올 때는 `VITE_TW_NET` 없이 다시 빌드한다.
